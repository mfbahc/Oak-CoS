# Board Briefing Refresh

Use this for board, committee, investor, lender, governance, or advisory meeting prep where the user needs a current briefing pack.

## Source Discipline

1. Search local/QMD context first for the existing project state.
2. Open the current briefing source, queue entry, and relevant project/company/domain page.
3. Search external connectors narrowly if authorized and available.
4. Save relevant source emails, attachments, trackers, and transcripts into a private artifact folder.
5. Convert only the attachments needed for the immediate briefing question.
6. Treat transcript-derived content as context, not official minutes, unless official minutes confirm it.

## Briefing Update Pattern

Update the canonical briefing source first, then regenerate the review copy/PDF if the workspace uses one.

Include:

- meeting objective and agenda;
- index of materials reviewed;
- recent updates since the prior brief;
- summary of each material;
- key issues and decision points;
- questions to ask by agenda item;
- voting guidance: approve, discuss, defer, or condition approval;
- open follow-ups and owner/date when known.

When new materials arrive:

- replace stale "missing" statements with current status;
- separate document-availability updates from substantive judgment;
- preserve source links/paths;
- avoid overstating tentative transcript or email language.

## Delivery Rules

- Owner-only delivery is allowed only when the user asks for it.
- External drafts or sends require explicit approval for that exact recipient and content.
- Remove internal provenance from external-ready notes unless the user asks to include it.

## Stop When

- relevant new materials are source-saved or confirmed already saved;
- the canonical briefing is current;
- the review copy/PDF is regenerated and spot-checked if applicable;
- the reading queue state is correct;
- tasks/observations/project notes are updated for material follow-ups;
- local search/QMD is refreshed after meaningful durable writes.
